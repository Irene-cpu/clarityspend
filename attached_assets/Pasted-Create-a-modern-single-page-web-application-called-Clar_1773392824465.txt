Create a modern single-page web application called **ClaritySpend**, a Decision & Spending Awareness Tool that helps users make smarter spending decisions by combining a simple expense tracker with a purchase decision assistant. The goal of the app is to give users a clear understanding of their current financial situation and help them quickly evaluate whether a potential purchase fits within their monthly budget. The application should be built using **HTML, CSS, and JavaScript**, and all data should be stored locally using **localStorage** so the app works without requiring user accounts or a backend. The interface should feel clean, modern, and minimal, similar to a simple financial dashboard, and it should be responsive so it works on desktop, tablet, and mobile screens. The layout should be a **single page application** with vertically stacked sections inside clean card-style containers. The top of the page should have a header showing the app name **ClaritySpend** and a short subtitle such as “Make smarter spending decisions.” The first section should be **Budget Setup**, allowing the user to set a monthly budget using a number input field labeled with the currency RM and a button labeled **Set Budget**. When the user sets the budget, the value should be saved to localStorage and immediately update the spending summary dashboard. The next section should be **Add Expense**, where the user can log daily spending. This section should include three inputs: an expense name text field (example placeholder “Grab Food”), an amount number input, and a category dropdown. The category dropdown should include options such as Food, Transportation, Shopping, Bills, Entertainment, and Other. There should be an **Add Expense** button that saves the expense entry into localStorage, clears the input fields, updates the spending summary, and adds the expense to the expense history list. Each expense record should store a name, amount, category, and date. The next section should be the **Spending Summary Dashboard**, displaying three visual summary cards labeled **Monthly Budget**, **Total Spent**, and **Remaining Budget**. Remaining budget should automatically be calculated as Monthly Budget minus Total Spent. The remaining budget indicator should visually change color depending on the situation: green when spending is healthy, orange when the user is approaching their limit, and red when the budget has been exceeded. After this section there should be a **Purchase Decision Helper** designed to help users evaluate whether they should buy something. This section should contain two input fields: purchase name and purchase price, and a button labeled **Evaluate Purchase**. When the user clicks the button, the system should compare the purchase price with the remaining budget and generate a recommendation. The decision logic should be as follows: if the remaining budget after the purchase is more than 30 percent of the total monthly budget, display “Safe to Spend” in green; if the remaining budget is between 10 percent and 30 percent, display “Be Careful” in orange; if the remaining budget is below 10 percent, display “Risky Purchase” in red; and if the purchase exceeds the remaining budget entirely, display “Over Budget” in red. The recommendation should appear inside a visually highlighted result box. Below this section there should be an **Expense History** section showing a list or table of all logged expenses. Each row should show the date, expense name, category, and amount, with the newest entries appearing first. Each entry should also include a **Delete** button that allows the user to remove the expense; deleting an entry should update localStorage and immediately recalculate the totals. The visual design should follow a modern dashboard style with card-based sections, rounded corners, and soft shadows. The primary color should be deep blue (#1E3A8A), the secondary accent color should be teal (#14B8A6), the background color should be light gray (#F5F7FA), and cards should use a white background. Text should be dark gray (#1F2937) for readability. Status colors should include green (#10B981) for safe or positive states, orange (#F59E0B) for warnings, and red (#EF4444) for danger states. Buttons should have rounded corners, hover effects, and smooth transitions. The layout should remain responsive so that on smaller screens the cards stack vertically and buttons expand to full width. The code structure should remain clean and modular so future improvements such as spending charts, category insights, export features, or dark mode can be added later. The entire application should function fully on the frontend using HTML, CSS, JavaScript, and localStorage without requiring any external backend services.
